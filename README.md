# Аудиоплеер для Яндекс Диска — версия под Android

Плеер для длинных лекций и аудиокниг с Яндекс Диска: перемотка, продолжение с места остановки,
запоминание позиции для каждого файла, папки с несколькими файлами и плейлистом.
Работает полностью в браузере, устанавливается на телефон как приложение (PWA).

## Файлы

| Файл | Что это |
|---|---|
| `index.html` | сам плеер — вся логика и стили внутри одного файла |
| `manifest.webmanifest` | описание приложения для установки на Android |
| `service-worker.js` | кэш оболочки: приложение открывается без интернета |
| `icons/` | иконки 192 / 512 / maskable + иконка для ярлыка |
| `serve.py` | локальный сервер с правильными MIME-типами (нужен для установки) |
| `test-folder.mjs`, `test-android.mjs`, `test-share.mjs` | автотесты логики (jsdom) |
| `screenshots.py`, `shots/` | скриншоты мобильного и десктопного вида |

## Как открыть на телефоне

1. Запустите сервер: `python3 serve.py 8000` (в каталоге проекта).
2. Узнайте адрес компьютера в локальной сети (например `192.168.1.50`) и откройте на телефоне
   `http://192.168.1.50:8000/` — телефон и компьютер должны быть в одной Wi-Fi сети.
3. Для **установки** приложения нужен HTTPS (или `localhost`). Проще всего выложить папку на любой
   статический хостинг с HTTPS (GitHub Pages, Netlify, Cloudflare Pages) и открыть ссылку на телефоне.

## Установка на Android

1. Откройте плеер в Chrome.
2. Нажмите кнопку **«Установить на телефон»** в карточке добавления файла
   либо меню **⋮ → «Установить приложение»**.
3. Иконка появится на рабочем столе, приложение откроется без адресной строки.

## Что даёт мобильная версия

- **Экран блокировки и шторка**: название файла и папки, пауза, перемотка ±10 сек, ⏮/⏭.
- **Фоновая работа**: экран можно гасить — звук продолжается.
- **Wake Lock**: пока играет — экран не гаснет сам (когда приложение открыто).
- **Мини-плеер** внизу экрана: название, прогресс, пауза, переход к файлам — когда основной плеер прокручен.
- **Кнопка «назад»** в подпапке ведёт на уровень выше, а не закрывает приложение.
- **Сохранение позиции** в памяти телефона: закрыли браузер — при следующем запуске продолжите с того же места.
- **Крупные тач-цели** (не меньше 44 px), увеличенная зона перемотки, поля с шрифтом 16 px
  (Android не зумит страницу при вводе), учёт выреза экрана (`env(safe-area-inset-*)`).

## Горячие клавиши (для клавиатуры/десктопа)

`Пробел`/`K` — пауза, `J`/`L` и `←`/`→` — ∓10 сек, `Shift+J/L` — ∓30 сек,
`P`/`N` — предыдущий/следующий файл, `↑`/`↓` — громкость, `M` — без звука, `0–9` — переход по файлу.

## Одна ссылка: плеер + папка

Плеер принимает ссылку на Диск в параметре `url`, поэтому «объединённая» ссылка — это обычный URL:

```
https://seva41seva.github.io/audio-player/?url=https%3A%2F%2Fdisk.yandex.com%2Fd%2FFHXwwZug9rUp8A
```

Правило простое: `адрес плеера` + `?url=` + `ссылка на папку, закодированная для URL`.
Закодировать можно в один шаг:

```bash
python3 -c "import urllib.parse,sys; print('https://seva41seva.github.io/audio-player/?url=' + urllib.parse.quote(sys.argv[1], safe=''))" 'https://disk.yandex.com/d/FHXwwZug9rUp8A'
```

Либо в JavaScript прямо в консоли браузера на странице плеера:

```js
location.origin + location.pathname + '?url=' + encodeURIComponent('https://disk.yandex.com/d/FHXwwZug9rUp8A')
```

Поддерживаются варианты: `?url=`, `?u=`, `?folder=`, `?link=`, `?public_key=`, `?src=`,
а также хеш `#url=…` и `#<ссылка>`. Ссылка может быть закодирована дважды или прийти без `https://` —
плеер поймёт.

Ещё удобнее: откройте папку в плеере — адресная строка сама становится готовой ссылкой,
а кнопка **«Поделиться»** копирует её в буфер. Если вставить такую ссылку обратно в поле ввода,
плеер вытащит из неё ссылку на Диск.

## Почему на GitHub Pages не воспроизводилось (исправлено)

**Яндекс Диск отдаёт `403` на прямые ссылки, если запрос пришёл с чужого `Referer`.**
Локально файл открывается через `file://` — там заголовка `Referer` нет, поэтому всё играло.
GitHub Pages всегда отправляет `Referer: https://<user>.github.io/...`, и Яндекс режет такой запрос.

Замеры на живом API (`downloader.disk.yandex.ru`):

| Запрос | Ответ |
|---|---|
| без `Referer` | `302` → `206` (файл отдаётся частями, играет) |
| `Referer: https://myuser.github.io/` | **`403`** (тело 15 байт) |
| `Referer: https://disk.yandex.ru/` | `302` (свой источник разрешён) |

В браузере это выглядело как `MEDIA_ERR_SRC_NOT_SUPPORTED (code 4)` — «плеер не может воспроизвести файл».

Что сделано в коде:

1. `<meta name="referrer" content="no-referrer">` — отключает `Referer` для всех запросов страницы,
   включая загрузку аудио. Это и есть основное исправление.
2. `referrerpolicy="no-referrer"` на `<audio>`.
3. `referrerPolicy: "no-referrer"` и `credentials: "omit"` во всех `fetch()`.
4. Кнопка «Скачать» открывает ссылку через `<a rel="noopener noreferrer">`.
5. Если прямая ссылка всё же протухла (живёт несколько часов) — плеер автоматически запрашивает
   новую и продолжает с того же места.

### Как обновить сайт на GitHub Pages

1. Замените в репозитории `index.html` и `service-worker.js` (и при необходимости остальные файлы).
2. Дождитесь сборки Pages (1–2 минуты; CDN GitHub кэширует до ~10 минут).
3. Откройте сайт и обновите страницу. Service worker обновится сам (версия кэша поднята до `v2`);
   если видите старую версию — закройте вкладку и откройте снова либо «Обновить с очисткой кэша».

Проверить, что дело именно в Referer, можно в DevTools → Network: запрос к `downloader.disk.yandex.ru`
должен вернуть `302`, а не `403`. В заголовках запроса `Referer` должен отсутствовать.

## Предусилитель («Усиление»)

Регулятор в блоке плеера: 100% по умолчанию, вправо — до 300%.
Нужен для тихих записей, которым не хватает громкости даже на максимуме телефона.

- Сигнал идёт через Web Audio: `mediaElement → GainNode → лимитер → выход`.
- Лимитер (компрессор −1.5 дБ, ratio 20) сглаживает пики, поэтому на 200% громкость растёт
  примерно в 1.6–2 раза без резкого «кваканья»; на 250–300% на громких записях возможны искажения.
- Обычный регулятор громкости продолжает работать независимо — усиление умножается на него.
- Настройка запоминается в localStorage и применяется к новым файлам.
- CORS: Яндекс отдаёт `access-control-allow-origin: *`, поэтому для его файлов плеер включает
  `crossOrigin="anonymous"` — без этого Web Audio выдавал бы тишину.
- Для источников без CORS (произвольные прямые ссылки) усиление отключается с подсказкой,
  чтобы не получить тишину вместо звука. Локальные файлы и Яндекс Диск работают.
- Кнопка ↺ рядом с ползунком возвращает 100%.

## Автопереход к следующему файлу

Переход запускается из трёх независимых мест, чтобы «через раз» не случалось:

1. Событие `ended` — обычный путь.
2. **Обрыв у конца файла**: если приходит `error`, а до конца меньше 20 секунд, файл считается
   законченным и включается следующий (раньше в этом случае трек начинался заново с нуля).
3. **Сторож**: раз в секунду проверяется, не «залипло» ли воспроизведение на последней секунде —
   если время не двигается 2.5 секунды, переход выполняется, даже если `ended` не пришёл.

Дополнительно:

- ссылка на следующий файл запрашивается заранее (за 90 секунд до конца) и кладётся в кэш,
  поэтому переход не ждёт сеть;
- `play()` вызывается через обёртку: если браузер отклонил автозапуск (частая причина на телефоне),
  показывается подсказка «Следующий файл готов — нажмите ▶», которая держится на экране
  и запускает воспроизведение по первому касанию;
- защита от двойного срабатывания (интервал 1.2 с) и от перехода после последнего файла.

## Ограничения

- Ссылка на папку должна быть публичной: «Поделиться» → «Доступ по ссылке».
- Прямые ссылки Яндекс Диска временные — плеер запрашивает новую при каждом открытии.
- iOS поддерживает установку через «Поделиться → На экран «Домой»», но управление с экрана
  блокировки там реализовано иначе и работает частично.
